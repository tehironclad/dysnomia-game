# Multiplayer audit before release 0.9.5 (2026-11-26)

**Branch:** `audit-net` (local, not pushed) · **Base:** `b3ed97f` · Scope: `scripts/net/` (client, server, protocol,
presence, remote players, voice, invites, events, names, bumps), `scripts/games/net_match.gd`, `wager.gd`,
`scripts/ui/notify/`, the activity feed, and where a finding led there, the tables' seats and `PlaceBase`.

The question: will real players on release 0.9.5 against `wss://game.enterdysnomia.com` (a headless Godot server
behind a Cloudflare tunnel) see each other, talk, play and wager correctly, and can anyone break or abuse the
server? The wallet/payment pipeline was not changed (§22 rules hold: nothing here moves funds or signs anything new).

## Findings

Severity is for players of 0.9.5. "Fixed" commits are on `audit-net`.

### High

| # | Finding | Status |
|---|---|---|
| H1 | **No presence inside places.** Walking into the arcade, the pub, the QING room or the Void left the server room (`NetPresence` lived only in the territory): the player vanished for everyone, saw nobody, and "say" chat and voice stopped. "Join me" to the arcade and every head-to-head game (played *in* the arcade) brought two players to a room where they could not see each other. | Fixed `c078424`: each place joins `<qing>/arcade|pub|hall`, the Void `<VOID>/void`. Checked in the real client: Join me → warp → door → `<qing>/arcade`, a bot in there drawn, its say-chat shown (`arcade_remote.png`). |
| H2 | **The live server is older than the client.** `wss://game.enterdysnomia.com` welcomes with `features: ["info","invites","bump"]` (no `"events"`, no `boot`): no activity feed, and none of the fixes below. | **Needs the owner**: re-run `tools/install-server-linux.sh` from this branch once merged. |

### Medium

| # | Finding | Status |
|---|---|---|
| M1 | **Voice playback had no jitter buffer.** Each 20 ms frame was pushed as it came and playback started with one frame queued; frames arrive 17 ms apart typically but up to 55 ms on localhost alone (147–480 ms from a slow sender), so the generator ran dry. Measured in the receiving game's output: gaps of 53–162 ms, 10 of 54 windows below 0.9 correlation. | Fixed `01ffc02`: 80 ms prefill (again after running dry), tail flush, stop after 2 s idle. After: **no gaps**, continuous alignment, 1 of 54 windows below 0.9. |
| M2 | **The mic ring dropped audio on hitches.** AudioEffectCapture's default 0.1 s buffer overflows whenever a frame takes longer (loading, a weak PC): measured holes of 174–290 ms in what the server relayed. | Fixed `01ffc02`: 0.5 s ring. After: 804 frames for 16.1 s held, no holes. |
| M3 | **Resampler timing error.** The 44.1/48 kHz → 16 kHz box filter sat on the nearest input sample, dropping the fraction: ~15 dB SNR at 1–3 kHz. | Fixed `01ffc02`: interpolated box (27.7 dB at 44.1 kHz, 31 dB at 48 kHz); chunked = whole (test). |
| M4 | **Server script errors from content.** `String({})`/`int([])` on any JSON field, and short `C_STATE`/`C_PING` read past their end: one error with a backtrace per message, not counted as a strike (a log flood any guest could cause), handlers stopped half way. Found by a 263-message barrage (wrong types for every field of every message type, every binary type truncated). | Fixed `77514d5`: typed reads everywhere, exact binary sizes (a strike). The barrage now prints nothing; it is part of `net_selftest`. |
| M5 | **Simultaneous sign-ins refused after the signature.** Over 4 checks a second the server answered "server busy": the player had already approved the signature in their wallet and stayed a guest (20 players at once: 3 guests). | Fixed `77514d5`: checks wait their turn (18 at once: all in 3.2 s). |
| M6 | **A server restart stranded live games.** Invites and games live in the server's memory; after a restart the client kept the game "playing", seated players at a table nobody could finish, moves refused "No such game.". | Fixed `77514d5` + `f0f1bf5`: the welcome carries a `boot` id; a new one (or "No such game." from an older server) marks the games abandoned with a note, nobody owes anything, the seat frees. Seen in the real client (`pool_restart_panel.png`). |
| M7 | **Every token reconnect arrived as a guest.** The token was sent after Net's join: the room got "a guest arrived" and the tag went guest → name each time. | Fixed `f0f1bf5`: the token goes first; checked in `net_selftest`. |
| M8 | **Claimed names at the tables.** The table felt, its headline and the notes named players by the server's record ("Bob (0xc0d4…)"): the player's own claim, which the rules say is never shown (anyone could sit down as "Sunny"). | Fixed `f0f1bf5`: the chain's name (Net.names) or the short wallet; seen in the real client. |
| M9 | **Line and invisible characters.** U+2028/2029 (a fake second line under a speaker's), word joiners, invisible operators, BOM (say-chat), soft hyphen, Arabic letter mark, Hangul fillers (blank names), tag characters were kept in say-chat, names and room lines. | Fixed `77514d5` (`NetProto.hidden_char`, also `ChatLines`). BBCode was already escaped. |

### Not fixed (and why)

| # | What | Why / recommendation |
|---|---|---|
| R1 | "Signed in" proves a key, not a player: throwaway keys pass every signed-in limit (invites, boards, events, chat). Board spam is bounded (500 boards × 500 rows) but a full file is large to save every 10 s. | A policy decision: e.g. require a LAU (one chain read on sign-in) for submits and invites, or rows per wallet-age. |
| R2 | The notification panel re-lays out when the online list refreshes (30 s): a button can move under the cursor (seen: "Confirm the stake" moved 21 px; "Concede" sits next to it). | UI file outside this audit's scope: keep the online list's height fixed or confirm Concede. |
| R3 | Twenty-One is fair only while the server's clock is right (documented, §8b). | Keep NTP on the box (`timedatectl`). |
| R4 | A flood of bogus signatures from many connections now queues ahead of honest ones (≤ 5 per connection, 200 connections: worst case ~4 min), where it used to make them "busy". | Acceptable; a per-IP queue needs the real IP the tunnel hides. |
| R5 | A first sign-in by signature joins as a guest, then signs ("A guest arrived", then "came online"). | Truthful; a token sign-in (every later launch) is already in order. |
| R6 | No echo cancellation or noise gate; ADPCM 16 kHz (≈ 21 dB SNR codec-only). | Push-to-talk limits echo; Opus would need a GDExtension. |
| R7 | The status line under the activity feed has no outline (hard to read over bright scenery). | Cosmetic. |

## Voice: what is measured and what needs people

**Measured here** (localhost server, 4-core container):

| Path | Signal | Result |
|---|---|---|
| Encoder → server → decoder (bots) | band-limited noise, 9.5 s | 477/477 frames, in order, latency median 28 ms (p95 33), corr 0.996, SNR 21 dB |
| **Game mic** (PulseAudio source → AudioStreamMicrophone → capture → resampler → ADPCM) → server → bot | same, push-to-talk held with xdotool | before: holes of 174–290 ms, SNR 8.7 dB; **after: no holes, corr 0.965, SNR 11.3 dB** (the source loop's own 63 ms restarts aside) |
| Bot → server → **game speaker** (RemotePlayer AudioStreamPlayer3D → PulseAudio sink) | same, the bot circling the player at 2 m | before: gaps 53–162 ms; **after: no gaps**, corr 0.976 |
| Distance falloff (same, circles of radius R) | RMS at the game's output | 3 m 0.060 · 15 m 0.009 · 35 m 0.0025 · 50 m silence (server radius 40 m) |
| Guests | `net_selftest` | a guest's frames are not relayed; guests hear |
| Mute | code review | `Net._on_voice` drops muted wallets and "mute everyone" before decoding |

**Needs two people with microphones:** real voices (not noise) through the real tunnel (its jitter decides whether
80 ms is enough), Windows' default WASAPI device (and "Let desktop apps access your microphone" in Windows privacy
settings), macOS's permission prompt on the first mic open (the export preset needs `privacy/microphone_usage_description`
and `codesign/entitlements/audio_input`: **present in the other audit's tree**, `export_presets.cfg` lines 93–96, not on
this branch; without the description macOS kills the app when the mic opens), Linux PipeWire, headsets vs speakers
(no echo cancellation), the F2 "Online & voice" device list, and a noisy room.

## Load (20 players, `tools/net_load.gd`)

20 connections in 1.3 s; 18 signed in within 3.2 s (2 guests); everyone saw the other 20 (incl. a game client).
One listener: 20 KB/s in (presence 3.3 KB/s, voice 16.9 KB/s from 2 talkers), 0.2 KB/s out, RTT ~20 ms. The server
sent 386 KB/s (3.1 Mbit/s of payload), CPU 5–15 % of one core, RSS flat at ~358 MB. Three reconnect storms (all 20
drop and return): no ghost connections, everyone sees everyone.
